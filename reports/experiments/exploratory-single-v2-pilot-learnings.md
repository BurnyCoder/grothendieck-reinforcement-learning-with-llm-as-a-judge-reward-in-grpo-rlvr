# Indexed single-call pilot: execution and reward observations

This development check exercises the current exploratory instrument, the real
verifier, four-completion groups, backward work and checkpoint recovery. The
[generated tables](exploratory-single-pilot.md) derive from archived boundary
records; complete prompts, responses and assessments accompany those records.
All pilot updates are excluded from comparative initialization.

The first boundary saved successfully. Positive scores without an evidence ID
caused a bounded retry; its invalid output was retained and no reward was issued
until a complete assessment passed validation. Indexed extraction prevented the
quotation-copying failure that terminated the earlier attempt. These attempts
did not generate identical policy text, so their timing difference is not a
controlled comparison of citation protocols.

The first sampled batch illustrates a separate limitation: missing or repeated
final-answer tags and malformed polynomial products lost correctness reward.
Correct GCD solutions received varying theory credit and no novelty credit.
They used conventional factorization methods. This is execution evidence and
an observation about the incentive supplied by an unqualified judge; it does
not establish that the reward encourages creative mathematical understanding.
The fixed correctness-only comparison and independent/transfer measurements
remain necessary. Do not change the rubric in response to these pilot scores.

Resumption loaded the saved boundary, advanced to different development tasks,
completed a nonzero-learning-rate update and saved the next checkpoint. The
[second boundary record](../development/feasibility-exploratory-single-step2.json)
contains the adapter comparison, optimizer/scheduler/RNG/cache file inventory,
data position and measured memory. The warmup boundary used zero learning rate;
the resumed adapter changed. This demonstrates execution and recovery, not an
improvement in mathematics. The batches contain different tasks, so their
accuracy difference is not a learning-effect estimate.

The second batch also received no novelty credit. Its theory scores varied,
including a low score for a conventional explanation. No threshold was weakened
and no accepted opinion was rerolled for a more favorable score. Runtime scenarios
use only this instrument's measured intervals and remain separate from historical
non-thinking and specialist measurements. They exclude baseline generation,
independent evaluation, transfer and publication. Future answer correctness,
lengths and retries can change the actual cost substantially.

The selected Qwen3.5 policy remains feasible on this machine. Continue with the
registered base checkpoint and fixed comparative budgets. The
[saved console warnings](../development/exploratory-single-runtime-warnings.json)
report reference PyTorch causal-convolution kernels; no optimized-kernel
throughput claim is made. This check does not qualify either judge.
