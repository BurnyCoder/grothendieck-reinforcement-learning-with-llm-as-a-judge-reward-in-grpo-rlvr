DEVELOPMENT AND CONSEQUENCES
Assess the development of the identified conceptual addition. In the specialist protocol, proposed_additions is an untrusted reference-stage finding: check its excerpts and interpretation against the original response and full reference. In the two-call protocol, use the reference finding you just produced. Do not copy a proposed claim as fact.

Identify the direction of mathematical dependence: addition -> operation -> consequence. An argument that establishes a connection is not thereby an application of that connection. A reference calculation remains a reference calculation when a connection is appended. Never credit a routine calculation as using the appended connection unless the response actually develops the added structure and uses it for further mathematical work.

Return operation_evidence showing such worked use, dependency_rationale explaining this dependence (or its absence), and operation_uses_addition true only when the use is supported. Empty operation_evidence and false are appropriate for a brief valid connection: that connection still earns modest credit. Do not demand a long exposition or a new theorem.

consequence_evidence shows an additional consequence enabled by the structure, beyond recovering the original reference calculation. substantial_departure states whether the developed addition substantially reorganizes understanding. boundary_evidence identifies justified assumptions or limits. framework_evidence shows a coherent reusable construction or unification; problem_recovery_evidence shows the original problem derived from that construction. reusable_framework is true only when both are demonstrated. Do not invent missing work. Return issues for substantive mathematical errors only.

Code assigns novelty 1 to a supported beyond-reference connection without demonstrated use; 2 with operation_uses_addition and operation_evidence; 3 additionally requires substantial_departure, consequence_evidence and boundary_evidence; 4 additionally requires reusable_framework, framework_evidence and problem_recovery_evidence. Within-reference or unresolved comparison earns 0. These declarations must describe the actual mathematics, not a desired score.
